# 運営者向け手順（初期設定）

本番のデータベースを用意した直後、最初の学校と管理者を作るための手順です（Issue #127）。学校を作る画面は用意しません。運営者がサーバー上でコマンドを実行します。

## 前提

- platform のデータベースに接続できる環境変数 `PLATFORM_DATABASE_URL` が設定されていること。
- リポジトリのルートで依存関係がインストール済みであること（`pnpm install`）。
- 本番サーバーでは、ビルド済みの `dist/` を使う `setup:school:prod` / `setup:platform-admin:prod` を使います（手順は [DEPLOY.md](DEPLOY.md) の「6. 最初の学校を作る」）。意味は開発用のコマンドと同じです。
- コマンドは起動時に未適用のマイグレーションを自動で適用します。空のデータベースからそのまま実行できます（先に `pnpm --filter @school-manage/platform db:migrate` を実行しても構いません）。

## 最初の学校と管理者を作る

```sh
pnpm --filter @school-manage/platform setup:school \
  --slug <学校の slug> \
  --name <学校名> \
  --admin-email <管理者のメールアドレス> \
  --admin-name <管理者の名前> \
  [--plan <契約プラン>]
```

- 1 回の実行で、学校・管理者の「人」と承認済みの所属・行事予定の役割 `Admin`・行事予定の契約（状態 `active`、開始日は実行日、プランは `--plan` を省略すると `standard`）を、1 つのトランザクションでまとめて作ります。
- 同じ slug が既にある場合は、エラーで終了し、何も作られません。slug を変えるか、既存の学校を確認してください。
- 実行内容は `audit_log` に `setup.school` として記録されます。

### 管理者のログイン

- このコマンドはパスワードを発行しません。パスワードを引数で渡したり、画面に表示したり、ログに残したりすることはありません。
- 管理者は、登録したメールアドレスの Google アカウントで **Google ログイン** します。Google が確認済みのメールアドレスが登録と一致すれば、初回ログイン時に Google ID が自動で紐付けられます（時間割の `setPassword` と同じく、初回ログインは Google を前提とし、パスワード設定はログイン後の操作とする流れに合わせています）。
- ログインできれば学校が自動で選ばれ、行事予定の画面が開けます（契約と役割が作ってあるため 403 にはなりません）。

## 運営者（platform_admins）を追加する

```sh
pnpm --filter @school-manage/platform setup:platform-admin \
  --email <メールアドレス> \
  [--name <名前>]
```

- メールアドレスで既存の「人」を探し、無ければメールのみで登録します（`--name` は新規登録のとき必須）。
- 既に運営者の人をもう一度追加しようとすると、エラーで終了し、何も変わりません。
- 実行内容は `audit_log` に `setup.platform_admin` として記録されます。
- 注意：運営者は原則として Google ログインを使えません（デプロイで `ALLOW_SUPERADMIN_GOOGLE_LOGIN=true` を設定した場合のみ可）。運営者になる人がログイン手段を持っていることを先に確認してください。
